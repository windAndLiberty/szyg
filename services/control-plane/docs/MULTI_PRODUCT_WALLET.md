# 多产品钱包与账本

## 产品边界

控制平面共享一套服务和定价，但账号归属于固定产品：

- `szyg_private`：私域版，只允许管理员创建或邀请账号。
- `xiaoyu_public`：微软商店公域版，后续开放自助注册。

邮箱只在产品内唯一，因此同一邮箱可以分别拥有公域和私域账号。登录请求携带
`product_id`，访问令牌和离线许可证也写入该值。服务端会核对令牌产品与用户产品，
管理员只能查询和操作自己产品内的用户、钱包及用量。

## 唯一计费策略

两个产品使用同一价格版本和换算规则：

- 1 人民币元 = 100 Credits。
- 用量结算使用 `usage_accounting.py` 的统一价格版本和快照。
- 当前目标上游成本占 Credits 收入的 60%，目标毛利率为 40%。

产品差异只影响注册、界面和运营方式，不改变单位价格。

## 钱包与不可变账本

`credit_wallets` 保存当前余额和预留余额，是余额查询的唯一来源。每个用户在每个产品
中只有一个钱包。`credit_ledger_entries` 是追加式账本，记录每次入账和成功消费后的余额。
已写入账本的记录不修改；冲正和退款使用新的反向记录。

旧的 `credit_transactions` 表不再参与余额、账单或充值计算。由于系统尚未商用，本次
迁移不导入旧测试流水，并在备份后清空旧测试记录；升级后为现有用户创建零余额钱包，
由管理员重新发放测试 Credits。

关键不变量：

1. `available = balance - reserved`，可用余额不能被并发请求重复占用。
2. 调用上游前先锁定钱包并预留保守估算的 Credits。
3. 成功后释放预留，按真实用量扣款，并以用量事件 ID 幂等写入一条账本记录。
4. 失败或任务超时后释放预留，不产生消费账本记录。
5. 管理员充值使用业务参考号幂等，同一参考号重试不会重复入账。

## 支付宝接入边界

支付宝接入时新增支付订单状态机，订单至少保存产品、用户、钱包、人民币金额、Credits、
商户订单号、支付宝交易号和状态。服务端验签并确认金额后，使用商户订单号作为幂等键
调用钱包入账；客户端支付成功页面不能直接修改余额。

当前钱包和账本不需要支付宝账号或密钥。开始实现真实支付下单、异步通知验签和退款时，
需要申请支付宝开放平台应用并提供应用 ID、应用私钥、支付宝公钥、异步通知域名及所开通
的支付产品。到该阶段再申请，避免在接口尚未定稿时反复配置。

## 上线顺序

1. 数据库执行 `alembic upgrade head`。
2. 启动控制平面；启动过程会为所有现有用户建立零余额钱包。
3. 管理员按测试需要重新发放 Credits。
4. 私域桌面端继续使用默认产品 `szyg_private`。
5. 公域桌面端在登录和后续注册请求中固定发送 `xiaoyu_public`。
