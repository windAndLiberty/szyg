# szyg 前端重构计划：从功能堆砌到 AI 员工 + Hermes 超级员工双核驱动

> 核心思路：借鉴炼刀AI（AI员工 × 语音控制 × 全链路自动化）+ 百应AI（Multi-Agent协同 × 效果导向），将前端从「30+功能罗列」重构为「**AI员工（4个专业角色）+ 超级员工（总指挥/全能力对话）**」双核驱动架构。
> 
> **超级员工**：对标炼刀AI的核心交互界面，是系统唯一的「总指挥」角色，用户通过自然语言对话调用全部102个工具，实现全链路自动化。所有专业员工（内容/获客/转化/运营）本质上都是超级员工的「工作模式」或「任务委托对象」。

---

## 一、当前问题诊断

| 问题 | 现状 | 后果 |
|------|------|------|
| **导航过载** | 顶部5个栏目，内容工厂下塞了13个子项 | 用户认知负担极高，找不到功能 |
| **语义混乱** | 同一层级混合使用技术术语（AI导航、智能微剪辑）、业务术语（矩阵一键分发）、生造词（数字化员工矩阵墙） | 用户无法建立心智模型 |
| **功能未闭环** | AI绘画、AI一键智能成片、智能微剪辑、创作流水线分散在4个不同入口 | 一个视频创作流程需要跳5次页面 |
| **缺乏主入口** | 没有统一的「任务下达」和「进度监控」中心 | 用户不知道AI在做什么、做完了没 |
| **后端能力与前端展示错位** | 后端有清晰的「超级员工 × 四层权限」架构，前端完全没体现 | 产品核心竞争力被埋没 |

## 二、重构目标：「员工中心」架构

用户不需要理解30个功能，只需要理解**4个专业AI员工 + 1个超级员工**。

### 2.1 核心隐喻（借鉴炼刀AI）

- **炼刀AI**：用户说「炼刀，上班」，AI自动执行全流程
- **szyg**：用户在 **AI员工** 选择专业员工 → 下达任务；或在 **超级员工** 用自然语言直接指挥 → 自动拆解为子任务 → 分配给员工执行

### 2.2 双核架构：专业员工 + 超级员工

```
┌─────────────────────────────────────────────────────────────────────┐
│                         szyg 双核驱动架构                              │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   ┌──────────────────────────┐    ┌────────────────────────────┐ │
│   │  🤖 超级员工               │    │  👥 AI员工（4个专业角色）    │ │
│   │  ─────────────────────     │    │  ───────────────────────    │ │
│   │  自然语言对话入口            │    │  具象业务场景入口            │ │
│   │  用户说 → AI拆解 → 自动执行  │    │  用户选择 → 配置任务 → 执行  │ │
│   │                            │    │                            │ │
│   │  能力：全部102个工具         │    │  每个员工封装一个闭环        │ │
│   │  调用方式：自然语言/语音     │    │  调用方式：表单+向导        │ │
│   │  适用：复杂跨模块任务        │    │  适用：单一模块高频任务      │ │
│   │                            │    │                            │ │
│   │  示例：                     │    │  示例：                     │ │
│   │  "帮我发3条抖音并处理私信"   │    │  内容专员 → 生成视频 → 发布  │ │
│   │  → 超级员工自动拆解为：      │    │  获客专员 → 搜索截流 → 加微   │ │
│   │    1. 内容专员生成视频       │    │  转化专员 → 跟进客户 → 成交   │ │
│   │    2. 发布到抖音            │    │  运营专员 → 排班调度 → 报告   │ │
│   │    3. 获客专员处理私信       │    │                            │ │
│   │    4. 转化专员加微信         │    │                            │ │
│   └──────────────────────────┘    └────────────────────────────┘ │
│              ▲                                    ▲                 │
│              │         仪表盘（统一指挥台）        │                 │
│              └────────────────────────────────────┘                 │
│                                                                     │
│   用户路径：                                                         │
│   A. 新手/低频用户 → 用超级员工对话「一句话完成任务」                 │
│   B. 专家/高频用户 → 用 AI员工 直接操作「精确控制每个环节」            │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

| 员工角色 | 负责闭环 | 封装的能力（后端工具） | 对标对象 |
|----------|----------|------------------------|----------|
| **🤖 超级员工** | **全系统自然语言指挥** | **全部102个工具** | 炼刀AI核心（语音/对话控制） |
| **内容专员** | 素材 → 生成 → 剪辑 → 发布 | 内容发布(11) + 平台运营(8) + 视频剪辑(12) + AIGC生成(6) + 办公技能(12) | 炼刀AI内容工厂 |
| **获客专员** | 搜索 → 截流 → 互动 → 加微 | 视频搜索、评论管理、私信、竞品监测、自动回复 | 炼刀AI公域获客 |
| **转化专员** | 线索 → 跟进 → 成交 → 复购 | 客户管理、微信桥接、SOP、知识库、行为策略 | 百应AI销售转化 |
| **运营专员** | 排班 → 调度 → 监控 → 报告 | 调度引擎(10) + 日历 + 数据分析 + 监控 | 百应AI效果导向 |

> **关键设计**：超级员工不是第5个「并列」的员工，而是**凌驾于所有员工之上的总指挥**。它有一个**独立的对话界面**（对标炼刀AI的交互），用户用自然语言下达跨模块的复杂任务，超级员工自动拆解并委派给各个专业员工执行。用户也可以在 AI员工 页面直接操作某个专业员工（适合高频单一任务）。

### 2.3 用户核心路径（Onboarding）

```
登录 → 仪表盘（今日概览） → 选择入口：
                              ├─ 说一句话 → 超级员工对话 → 自动执行 → 验收结果
                              └─ 精确操作 → AI员工 → 选择专业员工 → 配置任务 → 执行监控
```

## 三、新信息架构

### 3.1 主导航（顶部）：4个模块 + 超级员工常驻入口

| 模块 | 名称 | 说明 | 用户路径 |
|------|------|------|----------|
| 🏠 **仪表盘** | 数据驾驶舱 | 全局概览、今日任务、员工状态、关键指标 | 每天登录先看 |
| 🤖 **AI员工** | 数字员工 | **专业员工入口**，4个员工的管理、任务下发、执行监控 | 高频精确操作 |
| 🏭 **内容工厂** | 内容资产 | 素材库、成片库、文案库、发布记录 | 查看内容成果 |
| 🎯 **营销拓客** | 线索客户 | 线索列表、客户跟进、成交记录 | 查看客户成果 |
| ⚙️ **系统设置** | 账号基建 | 平台账号、工具安装、团队管理、品牌配置（顶部右侧下拉） | 低频配置 |

**超级员工** 的入口设计：

```
方案A（推荐）：全局常驻悬浮按钮
├── 位置：页面右下角（FAB），或顶部导航栏右侧紧邻用户头像
├── 图标：闪电/机器人头像，带脉冲动画
├── 点击：右侧滑出超级员工对话面板（类似 Slack 的 threads 面板）
├── 面板宽度：400-480px，不占用整个页面
└── 面板内：对话历史 + 输入框 + 快捷指令

方案B：独立页面
├── 顶部导航增加「超级员工」菜单项
├── 点击进入全屏对话界面
└── 适合复杂长对话场景

推荐：方案A（常驻面板）+ 方案B（独立页面可展开）
```

> **为什么这样设计**：
> - 超级员工是「随时待命」的助手，不应该藏在二级菜单里
> - 常驻面板让用户可以随时唤起、随时对话、随时看到执行进度
> - 4个主导航 + 1个常驻入口，结构清晰，不增加认知负担
> - 内容工厂、营销拓客改为「结果沉淀」页面，不是操作入口（操作在 AI员工 或超级员工里完成）

### 3.2 AI员工（核心模块）：内部结构

AI员工是用户的主工作区，不是简单罗列，而是**按角色组织**。

```
AI员工
├── 员工概览（Dashboard within）
│   ├── 员工状态卡片（4个专业角色，每个显示：今日任务数/状态/最近完成）
│   └── 快捷指令：「一键上班」（所有员工启动当日任务）
│
├── 任务工作台（统一的任务入口）
│   ├── 新建任务（选择员工 → 选择任务模板 → 配置参数 → 提交）
│   ├── 执行中任务（实时进度、可暂停/终止）
│   └── 历史任务（已完成、失败、待审核）
│
├── 内容专员工作室（点击展开详细能力）
│   ├── 素材管理
│   ├── AI生成（文案/图片/视频）
│   ├── 视频剪辑
│   ├── 发布管理（含审核、排班、一键分发）
│   └── 日历排班
│
├── 获客专员工作室
│   ├── 搜索配置（关键词、平台）
│   ├── 截流任务（竞品视频、评论区）
│   ├── 互动管理（评论、私信）
│   └── 加微/线索提取
│
├── 转化专员工作室
│   ├── 线索管理
│   ├── 客户跟进（SOP流程）
│   ├── 微信桥接（自动回复、群发）
│   └── 成交记录
│
└── 运营专员工作室
    ├── 调度引擎（Cron/定时/触发）
    ├── 监控面板（平台健康、竞品动态）
    ├── 数据报告（内容效果、获客效果、转化漏斗）
    └── 日志审计
```

### 3.3 仪表盘设计

仪表盘不再是「统计数字展示」，而是**今日指挥台**：

| 区域 | 内容 | 借鉴 |
|------|------|------|
| 顶部快捷栏 | **超级员工快捷输入框（大）** + 「一键上班」按钮 + 语音指令按钮 | 炼刀AI语音控制 |
| 左侧员工状态 | 4个专业员工卡片 + **超级员工总指挥卡片**，显示当前状态（运行中/空闲/异常）+ 今日任务进度 | 炼刀AI数字员工概念 |
| 中间任务队列 | 执行中任务列表，实时进度条 | 真实操作反馈 |
| 右侧数据速览 | 今日发布数、新增线索数、新增客户数、转化率 | 百应AI效果导向 |
| 底部异常告警 | 失败任务、平台登录失效、风控提示 | 运营保障 |

> **超级员工在仪表盘的核心位置**：顶部放置一个显眼的输入框，用户可以直接输入指令，如「帮我发3条抖音视频并处理评论区私信」，超级员工自动拆解执行。这是对标炼刀AI「炼刀，上班」的核心交互。

### 3.4 超级员工对话界面（对标炼刀AI）

超级员工是 szyg 的**核心差异化功能**，必须有一个独立、专业、可信的对话界面。

#### 面板内部结构

| 区域 | 内容 | 说明 |
|------|------|------|
| **顶部标题栏** | 超级员工头像 + 名称「超级员工」+ 状态灯（运行中/空闲）+ 最小化/关闭按钮 | 让用户明确知道这是总指挥 |
| **对话历史区** | 滚动消息列表，支持用户消息和超级员工消息 | 用户消息右对齐，超级员工消息左对齐 |
| **超级员工消息类型** | 文本回复、工具调用卡片、执行结果卡片、错误提示、确认请求 | 不同消息类型不同样式 |
| **工具调用卡片** | 显示正在调用的工具名称、参数、执行进度（进度条） | 透明化 AI 的"思考过程"，提升信任感 |
| **执行结果卡片** | 任务完成后的结果展示（如生成的视频缩略图、发布成功的链接） | 可直接点击跳转详情 |
| **输入框区** | 多行文本输入 + 发送按钮 + 语音输入按钮（预留） + 快捷指令下拉 | 支持 Enter 发送，Shift+Enter 换行 |
| **快捷指令** | 预设常用指令：「一键上班」「生成今日内容」「检查平台状态」「处理昨日私信」 | 一键填充输入框 |
| **底部状态栏** | 当前模型、工具数量、网络状态 | 技术透明，增强信任 |

#### 交互设计

| 交互 | 行为 | 说明 |
|------|------|------|
| **点击悬浮按钮** | 右侧滑出对话面板（300ms 动画） | 面板外点击可关闭 |
| **发送指令** | 输入框 Enter 发送，显示"思考中"状态 | 发送后输入框清空 |
| **多步骤任务** | 每完成一步，对话区新增一条结果消息 | 用户可滚动查看历史 |
| **需要确认** | 显示确认卡片（如"检测到敏感操作，是否继续？"） | 用户点击后才继续执行 |
| **错误处理** | 红色错误卡片，显示错误原因 + 重试按钮 + 人工接管按钮 | 不中断对话流程 |
| **历史记录** | 支持查看历史对话，点击后可恢复上下文 | 使用 localStorage 或后端存储 |
| **快捷指令** | 点击预设指令，自动填充输入框并发送 | 减少用户输入成本 |

#### 技术对接

超级员工面板需要对接后端接口：
- **发送消息**：`POST /api/hermes/chat` (streaming SSE)
- **获取历史**：`GET /api/hermes/history`
- **取消任务**：`POST /api/hermes/cancel`
- **工具执行状态**：通过 SSE 实时推送进度

面板组件需要支持：
- SSE 流式接收（`EventSource`）
- 消息类型渲染（根据后端返回的 `type` 字段渲染不同 UI）
- 自动滚动到底部
- 断线重连

## 五、设计规范（Design System）

### 5.1 命名原则

- **使用具象名词，避免技术术语**：「内容专员」而非「AIGC Pipeline」，「客户池」而非「CRM线索看板」
- **统一后缀**：主入口用「中心」「库」「池」，工作区用「工作室」「工作台」，配置用「设置」
- **动作按钮统一**：「新建任务」「一键上班」「开始执行」「暂停」「验收」「重新派工」

### 5.2 状态系统（颜色语义）

| 状态 | 颜色 | 适用场景 |
|------|------|----------|
| 运行中 | 🟢 青色/绿色 | 员工工作中、任务执行中 |
| 待执行 | 🟡 琥珀色 | 排班任务、待审核 |
| 空闲 | ⚪ 灰色 | 员工待命 |
| 异常 | 🔴 红色 | 失败、风控、登录失效 |
| 完成 | 🔵 蓝色 | 任务完成、内容已发布 |

### 5.3 布局规范

- **员工卡片**：统一尺寸，头像+名称+角色+状态灯+今日任务数+进度条
- **任务项**：统一列表项，任务名称+指派员工+进度条+状态标签+操作按钮
- **内容预览**：媒体文件统一缩略图+悬浮播放/查看
- **抽屉/侧边栏**：详情页优先用右侧抽屉，非独立页面，减少跳转

## 六、重构实施路线图

### Phase 1：骨架搭建（优先级最高）

1. **重构 AppLayout**：顶部导航改为 4模块（仪表盘、AI员工、内容工厂、营销拓客）+ 超级员工常驻入口

4. **新建 AI员工**：员工概览 + 任务工作台（2个核心子页）
5. **路由重定向**：保留所有旧路由，重定向到新页面（兼容旧链接）

### Phase 2：员工工作室填充

1. 内容专员工作室：合并 ImageGen/VideoGen/VideoEdit/Pipeline/Publisher/PublishManage/Calendar/Scheduler

## 七、关键UX改进点

| 改进点 | 原设计 | 新设计 | 借鉴来源 |
|--------|--------|--------|----------|
| **主入口** | 顶部5个栏目，每个下面塞了8-13个选项 | AI员工 一个入口，按角色聚合 | 炼刀AI数字员工概念 |
| **超级员工** | 无统一入口，能力散落在Chat页面 | **全局常驻超级员工对话面板**，自然语言调用全部工具 | 炼刀AI核心交互 |
| **任务下达** | 用户需要知道哪个功能在哪个菜单里 | 选择员工 → 选择任务类型 → 配置参数；或超级员工一句话完成 | 百应AI Agent协同 |
| **执行反馈** | 无统一执行状态，需要手动去各页面查看 | 超级员工面板实时展示工具调用进度 + AI员工页面看任务进度 | 炼刀AI视觉反馈 |
| **语音控制** | 无 | 仪表盘顶部超级员工输入框 + 语音按钮（后续版本） | 炼刀AI语音控制 |
| **效果度量** | 数据统计分散在各页面 | 仪表盘统一展示今日核心指标 | 百应AI效果导向 |
| **异常处理** | 无统一告警 | 员工卡片上显示异常状态，一键修复；超级员工主动报告 | 企业级运维思维 |

## 八、总结

**一句话产品总结（重构后）：**

> szyg 是企业级智能数字员工平台。用户通过 **超级员工** 用自然语言一句话完成跨模块的复杂任务（如「帮我发3条抖音并处理私信」），或在 **AI员工** 页面直接操作4个专业员工（内容/获客/转化/运营）完成精确任务。超级员工实时展示工具调用过程，AI员工 按角色组织业务闭环。仪表盘提供统一指挥和效果度量，内容工厂和营销拓客沉淀业务成果。

**核心改变：**
- 从「功能列表」→「**双核驱动**：超级员工对话 + AI员工操作」
- 从「30+独立页面」→「8个核心页面 + 超级员工常驻面板」
- 从「用户找功能」→「**用户说话，AI执行**」
- 从「技术术语」→「业务语义」（AI员工、内容工厂、营销拓客）
- 新增 **超级员工对话界面**，对标炼刀AI核心体验，是产品的最大差异化
