# 领鹿员工（简称：llyg） 数字员工产品需求说明

## 1. 产品定位

领鹿员工（简称：llyg） 数字员工不是聊天机器人，也不是多个功能页面的集合，而是一名能够理解企业目标、使用企业资料并持续推进业务的超级员工。

用户不需要了解模型、接口或自动化工具，只需要表达希望达成的结果。例如：

> 帮我推广这款 AI 英语学习产品，寻找有需求的家长，准备内容并安排发布。

数字员工应当理解产品、分析市场、制定行动、生成内容、执行任务、跟进客户，并持续向用户反馈进度和结果。

## 2. 用户核心需求

中小企业老板和运营人员通常面临以下问题：

- 不清楚每天应该生产什么内容。
- 同时管理多个平台和账号，重复操作耗时。
- 发布、评论和客户跟进缺少统一记录。
- 找到潜在客户后，无法持续追踪和推进转化。
- 不知道哪些内容有效，也难以从历史数据中获得下一步建议。
- 已有企业资料、产品知识和运营经验没有被持续利用。

数字员工需要将这些零散工作连接成完整闭环：

```text
理解企业与产品
→ 发现市场机会
→ 生成和整理内容
→ 多平台发布
→ 评论互动与获客
→ 识别并跟进线索
→ 沉淀客户资产
→ 分析结果并持续优化
```

## 3. 数字员工的工作方式

### 3.1 面向目标工作

用户表达目标后，数字员工应主动拆解任务，而不是要求用户逐页操作。

它需要：

1. 阅读企业资料、知识库和历史内容。
2. 识别产品卖点、目标人群和营销场景。
3. 分析市场信息、用户需求和内容机会。
4. 制定能够执行的内容与获客计划。
5. 调用已有能力完成内容生成、素材整理、发布和跟进。
6. 在重要操作前请求用户确认。
7. 汇总执行结果，并提出下一步行动建议。

### 3.2 持续理解企业

数字员工需要逐步了解：

- 企业、品牌和产品信息。
- 核心卖点、价格、服务范围和适用人群。
- 品牌语言、内容风格和禁止表达。
- 已有素材、知识库和历史发布内容。
- 不同平台和账号的定位。
- 客户画像、常见需求和典型异议。
- 用户对生成内容的修改与采纳偏好。
- 历史发布、互动、线索和转化结果。

这些信息用于改善后续工作，但数字员工不能擅自修改企业事实，也不能替代用户作出高风险决定。

## 4. 三方平台账号管理

### 4.1 用户需求

用户需要在一个地方查看和管理用于内容运营的三方平台账号，不必反复打开不同平台确认登录状态。

账号管理应支持：

- 同一平台管理多个账号。
- 显示真实昵称、头像和可获取的基本数据。
- 清楚区分在线、需登录、需处理等状态。
- 登录、重新登录、刷新资料和移除本地账号。
- 将常用账号保存为发布配置档案。
- 每次发布前读取最新账号和配置档案，不使用过期信息。

### 4.2 平台范围

内容发布渠道可包括：

- 抖音
- 小红书
- 快手
- B站
- 视频号
- 微博
- 后续接入的其他内容平台

个人微信不属于内容发布账号。微信是私域营销的承接工具，应在营销获客模块中独立管理。

### 4.3 账号安全

- 平台登录信息保留在用户当前电脑。
- 不向其他用户共享账号状态和登录信息。
- 登录失效时暂停相关任务，不重复尝试敏感操作。
- 遇到验证码、账号限制或平台风险提示时交由用户处理。
- 移除账号时同时清理该账号在本机保存的登录状态和展示资料。

## 5. 内容生成与素材管理

### 5.1 内容生成

数字员工需要根据用户目标和企业资料生成：

- 文案
- 图片
- 视频
- 语音
- 图文草稿
- 由多个素材组合而成的视频方案

所有生成内容自动保存到用户设置的本地目录。用户可以从生成历史中选择真正需要的内容，将其采纳到“素材管理与发布”。

### 5.2 素材管理

素材管理是内容发布的唯一入口。用户可以：

- 查看已采纳的图片、视频、文案和图文素材。
- 搜索、筛选、全选或移除素材。
- 打开素材所在位置。
- 编辑文案和图文内容。
- 组合不超过五个素材生成图文或视频。
- 选择一个或多个素材进入确认发布。

领鹿员工（简称：llyg） 不直接删除用户磁盘上的原始文件。用户删除或移动本地文件后，系统应同步清理失效记录。

## 6. 多平台内容发布

### 6.1 发布流程

用户选中素材并点击发布后，数字员工应提供简洁的确认流程：

```text
选择素材
→ 选择平台账号或发布配置档案
→ 检查并编辑标题、正文和标签
→ 确认发布
→ 自动执行
→ 跳转发布看板查看结果
```

### 6.2 发布内容准备

- 单个完整图文素材应尽量保留原内容，不重复改写。
- 多素材组合发布时，数字员工应理解图片、视频和文案，再统一生成标题、正文、标签和图片顺序。
- 标题和正文需要遵守目标平台的长度与格式要求。
- 用户可以在确认发布前修改内容。
- 图片应按照内容语义插入到合适段落，而不是简单堆放。

### 6.3 多账号发布

- 用户可以选择单个账号、多个账号或一个发布配置档案。
- 每个账号形成独立发布结果，互不影响。
- 一个账号登录失效时，不应让其他账号的成功任务一起失败。
- 同一平台的多个账号应稳妥执行，避免短时间高频操作。
- 每次发布应清楚显示将要发布到哪些账号。

### 6.4 发布看板

发布看板只负责展示结果，不承担内容编辑和发布入口。

用户需要看到：

- 内容摘要
- 平台与账号
- 图文或视频类型
- 排队、发布中、已发布、失败或需处理
- 提交时间和耗时
- 人能理解的失败原因
- 可以获取时展示具体作品链接
- 无法稳定获取具体链接的平台可展示作品管理页

正在发布的记录需要提供明确进度反馈。未发布成功的记录不显示作品入口。

发布记录支持关键词搜索、状态筛选、排序、分页和自动归档，每页最多展示十条。

## 7. 公域评论获客

### 7.1 发现目标内容

数字员工根据用户输入的产品、客户和营销目标，在公开平台中寻找具有真实业务相关性的内容。

筛选标准包括：

- 内容是否与产品使用场景相关。
- 评论区是否存在目标客户。
- 用户是否表达了需求、困难、比较或购买意向。
- 内容是否适合品牌参与讨论。
- 是否存在明显平台风险或敏感话题。

不能仅因为关键词相同就认为内容相关。例如，“AI 英语学习产品”不应匹配与英语学习需求无关的娱乐或情感内容。

### 7.2 生成候选评论

用户勾选一个或多个目标视频后，数字员工生成五条可选评论。

候选评论应：

- 与原视频内容相关。
- 自然表达，不机械复制广告语。
- 不虚构体验和身份。
- 不诱导、骚扰或重复刷屏。
- 符合品牌语气和平台规则。
- 允许用户直接编辑。

用户选择其中一条评论后，可以将同一评论发送到已选择的多个目标内容。

### 7.3 自动评论

自动评论属于对外公开操作，必须经过用户确认。

执行要求：

- 发送前再次检查账号登录状态。
- 对发送频率和每日数量进行限制。
- 同一内容避免重复评论。
- 发送成功后保存原视频地址。
- 单个目标失败时，不影响其他目标的结果记录。
- 登录失效、验证码、账号风险和平台限制进入“需处理”。
- 不确定是否发送成功时，不得直接标记成功。

### 7.4 评论队列

由于一次操作可能向多个目标发送同一评论，队列应按“群发任务”聚合展示。

每条任务显示：

- 实际发送的评论。
- 目标平台和账号。
- 总目标数、成功数、失败数和待处理数。
- 创建时间、执行时间和当前状态。
- 展开后显示每个原视频地址及其独立结果。

队列记录应支持搜索、筛选、分页、归档和保留期限设置，确保用户可以回溯每次公开互动。

## 8. 线索识别与获客追踪

### 8.1 线索来源

线索可以来自：

- 智能截流筛选出的目标内容。
- 评论区中明确表达需求的用户。
- 机会监听发现的新互动。
- 用户手动录入。
- 私信或微信沟通产生的联系人。

### 8.2 线索判断

数字员工需要判断：

- 对方可能需要什么。
- 当前意向是高、中还是低。
- 需求证据来自哪条内容或互动。
- 是否适合立即回复。
- 下一步应评论、私信、添加微信、继续观察还是停止跟进。

判断结果需要说明依据，不能只给出一个分数。

### 8.3 跟进流程

```text
发现线索
→ 判断需求和意向
→ 生成回复建议
→ 用户确认
→ 写入沟通草稿
→ 标记跟进结果
→ 设置下次提醒
→ 更新客户阶段
```

每次跟进需要记录：

- 客户或线索标识。
- 来源平台和原内容。
- 历史互动。
- 本次回复内容。
- 当前客户阶段。
- 最近跟进时间。
- 下一步动作和提醒时间。

### 8.4 私域营销

私域营销是 AI 销售员工的工作台，负责将公域线索转化为可持续跟进的客户关系。

它应提供：

- 今日待跟进客户。
- 高意向客户。
- 超时提醒。
- 客户需求与来源内容。
- AI 回复建议。
- 打开当前电脑微信。
- 将确认后的内容写入微信草稿。
- 标记已跟进并设置下一次提醒。

v1 只支持当前电脑登录的一个个人微信。写入草稿或发送等敏感动作必须由用户明确确认，不允许静默发送。

## 9. 客户资产与转化

经过确认的线索应进入客户资产，而不是停留在一次评论记录中。

客户资产需要保存：

- 客户基本信息和来源。
- 需求、标签和意向等级。
- 评论、私信、微信等互动时间线。
- 当前转化阶段。
- 负责人或数字员工任务。
- 下一步行动和提醒。
- 成交、流失或暂缓原因。

数字员工需要帮助用户发现：

- 哪些客户长时间没有跟进。
- 哪些客户意向正在上升。
- 哪些回复更容易获得回应。
- 哪些来源带来的客户质量更高。
- 哪些客户需要人工优先处理。

## 10. 情报、分析与复盘

数字员工需要将外部公开信息、企业知识、发布记录、互动和客户结果结合起来，而不是简单展示爬取到的视频或账号列表。

用户最终应看到：

- 市场需求和用户痛点变化。
- 高价值关键词及其语义关系。
- 内容主题、互动和线索质量对比。
- 平台与账号的发布表现。
- 评论触达、回复和线索转化情况。
- 客户阶段分布和跟进效率。
- 可执行的下一步建议。

少量代表性内容可以作为证据展示，但情报的主体应是经过清洗、归类和解释的数据分析。

## 11. 人工确认与安全边界

### 11.1 必须确认的操作

- 最终发布内容。
- 自动评论和群发评论。
- 私信、添加联系方式和微信相关操作。
- 写入聊天草稿或发送消息。
- 修改客户关键状态。
- 账号风险提示后的继续操作。

### 11.2 必须暂停的情况

- 登录失效。
- 验证码或人机验证。
- 账号限制、封禁或安全警告。
- 页面结构异常，无法确认操作目标。
- 发布或评论结果无法判断。
- 素材文件缺失。
- 用户额度或权限不足。

### 11.3 用户控制权

所有长期任务都应支持：

- 查看进度
- 暂停
- 继续
- 取消
- 重试
- 人工接管
- 查看执行记录和失败原因

数字员工必须让用户知道它正在做什么、做到了哪里、哪里需要协助。

## 12. 产品成功标准

数字员工是否真正有价值，不以页面数量或生成次数衡量，而以业务结果衡量：

- 用户从提出目标到开始执行所需的操作更少。
- 多平台发布成功率稳定提升。
- 登录失效和平台异常能够被准确识别。
- 评论记录和目标内容可以完整回溯。
- 高意向线索能够及时进入跟进队列。
- 客户跟进不再因遗漏而中断。
- 企业资料和历史经验能够改善后续结果。
- 用户能清楚看到数字员工带来的时间节省、内容产出、客户机会和转化进展。

最终体验应当是：

> 用户不是在操作一套复杂软件，而是在管理一名可靠、可确认、可追踪、会持续进步的超级员工。
