## ⚠️ 研究方法论与置信度声明

本报告功能设计基于对抗验证后的主张。关键约束：

- **Hermes 内核能力**: 全部 4 条主张通过 3-0 验证，基于官方文档和源码 — **可放心作为基础**
- **百应AI 技术细节**: 全部主张被证伪（Gravity Agentic OS 7 角色架构、RLHF 30% 转化提升均为 0-3）— **仅保留"全渠道销售对话"概念方向，不采用任何百应AI技术细节**
- **炼刀AI 功能**: 概念验证通过（语音桌面自动化 2-1），但用户投诉（新浪黑猫 3-0）揭示执行质量与宣传严重不符 — **采用功能方向，规避黑箱设计**
- **私域转化模块**: 置信度最低，无直接验证主张 — 标记为**远期探索，实施风险最高**

### 1.2 前后端模块映射（消解"操作 vs 沉淀"分裂）

后端有 6 个功能模块，前端有 5 个导航区 + 1 个全局面板。映射关系：

| 后端模块 | 置信度 | 前端操作入口（高频） | 前端沉淀/配置页（低频） |
|---------|--------|-------------------|---------------------|
| **M0** 超级员工编排核心 | 🔴 高 | SuperStaffPanel（全局面板，所有页面可用） | — |
| **M1** 内容生产工厂 + **M2** 多渠道发布引擎 | 🟡 中 | `ContentStudio`（AI员工子页，3 Tab：生产/发布/素材） | `ContentAssets`（内容资产沉淀页：成片库/文案库/发布记录） |
| **M3** 公域获客引擎 | 🟡 中高 | `AcquisitionStudio`（AI员工子页，4 Tab：搜索/截流/互动/监听） | — |
| **M4** 私域转化引擎 | 🟠 低 | `ConversionStudio`（AI员工子页，4 Tab：线索/跟进/SOP/知识库） | `CustomerAssets`（客户资产沉淀页：线索列表/跟进记录/成交记录） |
| **M5** 知识与技能中台 | 🔴 高 | 嵌入各工作室的"技能"标签 + SOP 引擎内嵌 | `SettingsSkills`（技能市场：浏览/安装/发布，独立设置子页） |
| **M6** 账号基建矩阵 | 🔴 高 | — | `SettingsPlatforms`（平台账号 + 安全评分）+ `SettingsSystem`（全局配置） |

> **关键设计决策**: 
> - **操作入口** (`/ai-staff/*-studio`) 和**沉淀页** (`/assets`, `/crm`) 是两套独立页面。用户在工作室完成操作，在沉淀页查看历史成果。不再有"内容工厂"这个模糊命名 — 它被拆分为 ContentStudio（操作）+ ContentAssets（沉淀）。
> - **技能市场** (`/settings/skills`) 获得独立设置子页，因为 agentskills.io 兼容是深研验证的高置信度差异化能力，不能降级为"嵌入员工卡片"。

### 1.3 导航结构（5 项一级导航）

| # | 导航项 | 路径 | 定位 | 包含 |
|---|--------|------|------|------|
| 1 | **仪表盘** | `/dashboard` | 每日入口 | 超级员工快捷输入框 + 员工状态卡片 + Kanban 实时看板 + 今日数据速览 |
| 2 | **AI 员工** | `/ai-staff` | 操作工作台 | 4 个专业工作室（内容/获客/转化/运营）+ 员工概览 + 任务看板 |
| 3 | **内容资产** | `/assets` | 内容沉淀（只读） | 成片库 / 文案库 / 发布记录 / 效果数据 |
| 4 | **客户资产** | `/crm` | 客户沉淀（只读） | 线索列表 / 跟进记录 / 成交记录 / 转化漏斗 |

> - 不再使用"内容工厂"（与 ContentStudio 混淆）→ 改为**内容资产**
> - 不再使用"营销拓客"（与 AcquisitionStudio 混淆）→ 改为**客户资产**
> - 不再声称"4 模块" → 明确为 **5 项一级导航**

## 二、六大核心模块

### M0: 超级员工多代理编排核心

> **置信度: 高** | Hermes Kanban (4/4) + Delegate Task (3/3) + Hub-and-Spoke (3/3)
> **前端呈现**: SuperStaffPanel（全局面板，非路由页面）

| # | 功能 | 说明 | 现有基础 |
|---|------|------|---------|
| 1 | **自然语言任务下达** | 用户在对话面板用自然语言描述任务，超级员工自动拆解为子任务并委派给专业代理。示例："帮我发 3 条抖音并处理私信" → 拆解 → 内容生产 → 多平台发布 → 评论监控 → 线索转化 | hermes_chat.py SSE 对话已可用 |
| 2 | **Kanban 持久化任务看板** | SQLite 7 状态（triage→todo→ready→running→blocked→done→archived），依赖引擎，崩溃恢复（zombie PID 检测） | Hermes Kanban v0.13+ 后端就绪，前端未集成 |
| 3 | **Delegate Task 子代理委派** | 同步 RPC 派生子代理，隔离上下文 + 受限工具集 + 独立终端（并发上限 3），Hub-and-Spoke 拓扑（协调器 M总 + 专业代理，代理间不直接通信） | delegate_tool.py 就绪，未暴露到 UI |
| 4 | **代理角色 Profiles** | 4 个专业代理角色，每个拥有独立 config/SOUL/memory/skills | Agent Marketplace JSON 定义存在，Profiles 隔离未实现 |
| 5 | **人机协同审核** | 关键决策点（发布前、高价值线索分配）插入人工审核，支持 Kanban comment/unblock 机制 | Publisher 有审批流，未整合 Kanban |
| 6 | **全链路执行日志** | 每次委派的完整审计轨迹：拆解→分配→工具调用→耗时→结果，支持回溯复现 | History 页存在，需整合 |

**独特价值**: 用户不需要理解 30+ 功能页面，只需一个对话入口。简单任务直接执行，复杂任务拆解为 Kanban 卡片并行委派。**"一句话运营矩阵"** 是 szyg 区别于竞品的核心竞争力。

**前端呈现**: SuperStaffPanel — 全局悬浮按钮（56px 圆形青色脉冲）→ 右侧滑出面板（420px 毛玻璃）→ 面板标题栏提供"展开全屏"按钮（解决长对话场景）。面板内 6 种消息类型：text / thinking / tool_call / tool_result / error / confirm。

### M1: 内容生产工厂

> **置信度: 中** | 炼刀AI 功能概念验证通过 (2-1)，但用户投诉警告执行质量问题
> **前端呈现**: ContentStudio（操作）+ ContentAssets（沉淀）

| # | 功能 | 说明 | 现有基础 |
|---|------|------|---------|
| 1 | **自然语言内容生产** | 输入主题/要求 → AI 自动选题 → 脚本生成 → 素材匹配 → 视频剪辑 → 字幕叠加 → 封面生成 | PipelineEngine 4 个预设模板，缺语音入口和端到端串联 |
| 2 | **AI 智能剪辑** | FFmpeg 裁剪/拼接/变速/文字叠加/音频替换/封面提取 + OmniParser v2 视觉定位 | VideoCutEngine + Vision Grounding 就绪 |
| 3 | **多模态内容生成** | 文生图（ComfyUI SD 2.1 + VolcEngine Seedream）、文生视频、图生视频、TTS、语音克隆。多后端自动故障转移 | VolcEngine + ComfyUI + ModelRouter 就绪 |
| 4 | **模板化批量生产** | 预设模板（口播/产品展示/知识科普/剧情/图文集），选模板→填素材→批量生成，品牌风格锁定 | PipelineEngine 框架就绪，模板内容待丰富 |
| 5 | **内容策略辅助** | 热点趋势分析 + 竞品内容监测 → 选题推荐 + 发布时间建议 + A/B 策略对比 | Web Search MCP + Monitor + AB Test 各组件独立 |

**独特价值**: 区别于炼刀AI"黑箱自动化"，采用**透明流水线 + 可干预节点**。每个生产步骤可视化，用户可在任意节点暂停、修改、重新生成。

### M2: 多渠道发布引擎

> **置信度: 中** | 多平台发布交叉验证
> **前端呈现**: 嵌入 ContentStudio Tab 2（发布管理），发布记录沉淀到 ContentAssets

| # | 功能 | 说明 | 现有基础 |
|---|------|------|---------|
| 1 | **一键多平台分发** | 同一内容发布至抖音/小红书/B站/快手/微信朋友圈，平台适配器自动格式转换 | 5 平台适配器就绪 |
| 2 | **发布审核工作流** | 草稿→提交→审核→驳回/通过→排期→发布→效果回溯，全流程 Kanban 状态追踪 | Publisher 审批流存在，未接 Kanban |
| 3 | **平台安全合规** | Stealth.js + 浏览器指纹伪装（WebGL/Canvas/语言/时区）+ 人类行为模拟（100-300ms 打字 + 贝塞尔鼠标 + 随机滚动）+ 内容合规检查 | Anti-Detection 445 行 + DeAI 引擎，已实现 |
| 4 | **发布效果追踪** | 跨平台表现对比（播放/点赞/评论/分享/转化），按平台/内容类型/时间维度分析 | ❌ 需新建平台数据回采 |

**独特价值**: 不是 API 群发，而是**平台适配 + 反检测 + 内容适配 + 效果归因**的完整闭环。反检测能力（445 行专用代码）解决了竞品最大痛点——账号被封。

### M3: 公域获客引擎

> **置信度: 中-高** | 4 个引擎全部已实现（共 2054 行代码）
> **前端呈现**: AcquisitionStudio（AI员工子页，4 Tab）

| # | 功能 | 说明 | 现有基础 |
|---|------|------|---------|
| 1 | **全网流量狙击** | 多平台关键词搜索 → 5 维质量评分 → 去重 → 优先级排序 | Intercept Engine 506 行 ✅ |
| 2 | **智能评论互动** | 批量评论 + 速率限制 + DeAI 去模板化 + 违禁词预检 | Comment Engine 628 行 ✅ |
| 3 | **7×24 监听雷达** | 后台异步轮询目标评论区，情感分析 4 分类（正面/负面/提问/线索），自动发现潜在客户 | Listen Engine 452 行 ✅ |
| 4 | **线索评分与分拣** | 4 维评分（0-100）→ A/B/C/D 分级 → 自动回复匹配 → 漏斗追踪（发现→回复→私信→认证→转化） | Convert Engine 468 行 ✅ |
| 5 | **A/B 策略实验** | 截流策略/回复模板/筛选条件的对比测试，统计显著性检验，自动推荐优胜策略 | AB Test + AB Results ✅ |

**独特价值**: 后端实现最完整的模块。区别于炼刀AI"关键词监控不准、私信转化率极低"的用户投诉（新浪黑猫 3-0 验证），szyg 的 DeAI 去模板化 + 5 维评分 + 4 维线索打分提供了更精细的质量控制。

### M4: 私域转化引擎

> **置信度: 低** | ⚠️ 无直接验证主张，基于概念定位 + Hermes 能力推断
> **前端呈现**: ConversionStudio（操作）+ CustomerAssets（沉淀）

| # | 功能 | 说明 | 现有基础 |
|---|------|------|---------|
| 1 | **金牌销售看板** | Kanban 漏斗：新线索→待跟进→沟通中→受阻→已成交→已流失。拖拽移动，自动触发下一阶段动作 | Leads 页面存在，未接入 Kanban 状态机 |
| 2 | **微信私域托管** | Windows UIA 自动化：自动通过好友/打招呼/打标签/发资料/朋友圈发布。会话存档 | WeChat Desktop 526 行 ✅ |
| 3 | **多平台私信统一** | 聚合抖音/小红书/B站私信到统一面板。AI 自动回复（RAG 驱动）+ 敏感问题转人工 | DM 页面存在，后端需跨平台聚合 |
| 4 | **SOP 销售流程引擎** | 自定义销售步骤 + 触发条件 + 等待时间 + 分支逻辑。超时自动升级，与 Kanban blocked 联动 | SOP Manager 就绪，缺触发/超时联动 |
| 5 | **客户画像与标签** | 跨平台数据聚合 → 360° 画像，智能标签（来源/偏好/意向/阶段） | Convert Engine + Memory FTS5 就绪，缺统一画像层 |
| 6 | **行为策略引擎** | 触发-条件-动作规则："关注 3 天未互动→自动发优惠券""加微 7 天未成交→转人工" | Strategy 前端页面存在，规则引擎待实现 |

**独特价值**: 百应AI 的"Multi-Agent 全自动销售"被证伪。szyg 走务实路线：**AI 负责标准化推进，人工负责关键决策**。用 Hermes Kanban 的真实人机协同能力实现透明自动化，而非 AI 黑箱。

> ⚠️ **远期标记**: 本模块所有功能标记为 Phase 5（远期探索），实施前需独立市场验证。

> **前端呈现**: SettingsSkills（设置子页，技能市场）+ 嵌入各工作室的"技能"标签

| # | 功能 | 说明 | 现有基础 |

| 2 | **企业知识大脑** | 文件导入 → 分块 → FTS5 全文索引 → RAG 检索。Context File 自动发现链 | Knowledge Base + Hermes Context Auto-Discovery ✅ |
| 3 | **文档智能处理** | docx 验证/创建/修订、pptx 验证/替换/重排/缩略图、xlsx 重算、pdf 表单填充/验证 | Document Skills 4 模块 ✅ |
| 4 | **SOP 知识库** | SOP 创建/版本管理/按需加载。代理执行任务时自动匹配相关 SOP 注入上下文 | SOP Manager 就绪，自动匹配注入待实现 |

### M6: 账号基建矩阵

> **置信度: 高** | 全部自研代码，已实现
> **前端呈现**: SettingsPlatforms（设置子页，平台账号 + 安全评分卡片）

| # | 功能 | 说明 | 现有基础 |
|---|------|------|---------|

## 三、独特价值总结矩阵

| 模块 | 核心差异点 | 竞品对比 | 置信度 |
|------|-----------|---------|--------|
| **M0 超级员工** | 对话即操作 — 一句话跨模块调度 | 炼刀AI 有对话但质量差；百应AI Multi-Agent 宣传未兑现 | 🔴 高 |
| **M1 内容工厂** | 透明流水线 — 每步可干预 | 炼刀AI 用户投诉"黑箱产废品" | 🟡 中 |

## 五、前端 UX 关键设计

### 5.1 页面类型定义（消解"操作 vs 沉淀"分裂）

| 页面类型 | 页面 | 特征 | 示例操作 |
|---------|------|------|---------|
| **操作工作台** | 4 个 Studio（Content/Acquisition/Conversion/Ops） | 可编辑、可提交、可执行 | 生成视频、发送评论、推进线索 |
| **只读沉淀页** | ContentAssets / CustomerAssets | 可搜索、可筛选、可导出，不可编辑 | 查看历史发布、查看成交记录 |
| **指挥台** | Dashboard | 全局概览 + 快捷入口 | 一键上班、查看今日数据 |
| **配置页** | Settings 及其子页 | 低频管理操作 | 绑定账号、安装技能、团队管理 |
| **全局面板** | SuperStaffPanel | 随时唤起，不占导航位 | 自然语言下达任务 |

### 5.2 核心交互原则

1. **渐进式复杂性披露**: 新用户只看到仪表盘 + 超级员工 FAB；高级用户探索 AI 员工中心
2. **空间即状态**: Kanban 列位置表达任务状态，而非表单字段
3. **AI 可见性**: 始终展示"AI 正在做什么"（当前步骤/进度/预计完成时间）
4. **可干预性**: 任何自动化步骤有"暂停/修改/重做"入口
5. **安全可见**: SettingsPlatforms 顶部展示安全评分卡片，确保护城河能力不被淹没

### 5.3 技能市场的前端定位

agentskills.io 兼容是深研验证的高置信度差异化能力。独立设置为 `/settings/skills`：
- 卡片式技能浏览器（分类/评分/下载量/兼容性）
- 一键安装 + 安装后自动出现在各工作室的"技能"标签
- 支持发布自定义技能包
- 与各工作室的"技能"标签双向联动（在市场安装的技能出现在工作室，在工作室创建的可发布到市场）

### 5.4 SuperStaffPanel 关键规格

| 元素 | 规范 |
|------|------|
| 默认形态 | 全局悬浮按钮（56px 圆形，青色脉冲动画）→ 右侧滑出面板（420px 毛玻璃） |
| 展开形态 | 面板标题栏"展开"按钮 → 全屏模式（类似 IDE 的 Zen Mode），用于复杂长对话 |
| 消息类型 | 6 种：text / thinking / tool_call / tool_result / error / confirm |
| 后端接口 | `POST /api/hermes/chat` (SSE) / `GET /api/hermes/history` / `POST /api/hermes/cancel` |
| `/chat` 迁移 | Phase 2 SSE 对接完成后，`/chat` → 重定向到 `/?panel=open`（仪表盘 + 自动打开面板） |

### 5.5 UI 命名规范

| 界面位置 | 应使用 | 不应使用 | 原因 |
|----------|--------|----------|------|
| 导航/面板/消息 | 超级员工 | Hermes | 用户不需要知道底层技术 |
| 员工卡片/工作室 | 内容专员 / 获客专员 / 转化专员 / 运营专员 | Agent / Pipeline | 业务语义 |
| 一级导航 | 内容资产 / 客户资产 | 内容工厂 / 营销拓客 | 明确沉淀定位 |
| 代码层面 | 保留 `hermes_chat.py`、`hermesStore` 等 | — | 技术实现不变 |
