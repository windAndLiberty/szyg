> 版本：v3.0
> 更新日期：2026-07-02
> 范围：前端页面功能 + 四大核心业务模块

## 1. 产品概述

### 1.1 产品定位

域灵（szyg）是一个 **AI 数字员工工作台**。运营人员通过自然语言对话，指挥 AI 完成内容营销全流程：搜索素材、生成图文/视频、剪辑加工、多平台发布。

核心体验：**"一句话指挥 AI 干活"**——用户只需描述需求，Agent 自主规划步骤、调用工具、反馈结果。

### 1.2 核心功能模块

| 模块 | 定位 | 优先级 |
|------|------|--------|
| 对话交互 | 全局入口，所有功能通过对话驱动 | P0 |
| AI 内容生成 | 文生图、文生视频、语音合成、文案生成 | P0 |
| 视频剪辑 | 裁剪、拼接、变速、叠加标题、音频处理、模板渲染 | P1 |
| 多平台发布 | 抖音/小红书/B站/快手/微信的视频和图文发布 | P0 |

### 1.3 用户角色

| 角色 | 场景 | 说明 |
|------|------|------|
| 运营人员 | 日常使用 | 通过对话下达指令，查看执行结果，管理对话历史 |
| 管理员 | 系统维护 | 管理平台登录态、配置 Agent 参数、处理异常 |

### 1.4 技术栈

| 层级 | 技术 |
|------|------|
| 前端 | React 19 + TypeScript + Vite + Tailwind CSS 3 |
| 后端 | FastAPI (Python)，端口 8000 |
| AI 引擎 | 火山引擎方舟（豆包系列模型）+ 本地 Ollama |
| 浏览器自动化 | Playwright (Chromium)，headless 模式 |
| 数据存储 | JSON 文件 |

## 2. 全局框架

### 2.1 应用外壳 (AppLayout)

应用的整体容器，分为三个区域：

| 区域 | 尺寸 | 功能 |
|------|------|------|
| 左侧导航栏 | 200px，可折叠至 64px | 品牌名称、分组导航菜单、折叠按钮 |
| 顶部栏 | 56px 高 | 左侧页面标题，右侧主题切换器 + 用户名 + 头像 |
| 内容区 | 填充剩余空间 | 超级员工页面使用 full-bleed 模式（无 padding） |

**导航菜单**：

| 分组 | 菜单项 | 路由 |
|------|--------|------|
| AI 员工 | 超级员工 | `/super-agent` |

**主题切换**：
- 亮色（Light）：暖纸色背景 `#F9F8F6`
- 暗色（Dark）：深炭色背景 `#1C1C1E`
- 切换后持久化到 `localStorage`，刷新自动恢复
- CSS 变量平滑过渡，无闪烁

**品牌配置**：
- 从 `GET /api/oem/config/default` 动态加载品牌名称
- 显示在导航栏顶部

### 2.2 认证系统

JWT Token 认证，对用户透明：

1. 页面加载时，前端自动用默认账号（admin/admin123）登录
2. 所有请求自动携带 `Authorization: Bearer <token>` 头
3. 收到 401 时自动重新登录，并发请求排队等待新 Token 后重试
4. 用户无感知，无需手动登录

## 3. 超级员工页面 — 对话交互模块

**路由**：`/super-agent`
**定位**：系统唯一入口页面，所有功能通过对话驱动

### 3.1 页面整体布局

```
┌──────────────┬──────────────────────────────────────┐
│              │  顶栏（56px）                         │
│  对话历史     ├──────────────────────────────────────┤
│  面板        │                                      │
│  (280px)    │  欢迎页 / 消息流                      │
│              │                                      │
│              │                                      │
│              ├──────────────────────────────────────┤
│              │  输入区                               │
└──────────────┴──────────────────────────────────────┘
```

- 页面高度：`calc(100vh - 56px)`，撑满顶栏以下所有空间
- 左栏对话历史面板：280px 宽（1024px 以下 240px，767px 以下隐藏）
- 右栏对话区域：填充剩余宽度

### 3.2 对话历史面板

#### 3.2.1 功能概述

左侧固定面板，展示和管理历史对话记录。用户可以快速切换不同对话、新建对话、对对话进行重命名/置顶/导出/删除操作。

#### 3.2.2 对话列表

**数据加载**：
- 页面加载时从 `GET /api/conversations` 获取所有对话
- 每条对话包含：`id`、`title`、`created_at`、`pinned`

**列表项展示**：
- 标题：对话标题（单行截断）
- 时间：相对时间格式
  - < 1 小时 → "刚刚"
  - < 24 小时 → "X小时前"
  - < 7 天 → "X天前"
  - ≥ 7 天 → 日期格式（YYYY/MM/DD）
- 置顶标记：置顶对话显示 📌 图标，排在列表最顶部
- 选中高亮：当前打开的对话项高亮显示（`accent-soft` 背景）

**空状态**：
- 无对话记录时，显示 💬 图标 + "暂无对话记录" 文字

#### 3.2.3 新建对话

- 点击面板右上角 **+** 按钮
- 清空当前消息列表和选中状态
- 页面切换到欢迎页状态
- 触发精选案例卡片重新加载

#### 3.2.4 选择对话

- 点击列表中的对话项
- 从 `GET /api/conversations/{id}` 加载该对话的所有消息
- 消息按顺序渲染到消息流
- 自动滚动到底部，展示最新内容

#### 3.2.5 右键菜单

在对话项上右键点击，弹出上下文菜单（自动调整位置避免溢出屏幕）：

| 操作 | 交互细节 | API |
|------|----------|-----|
| 重命名 | 弹出输入框，预填当前标题，校验非空 | `PUT /api/conversations/{id}` |
| 置顶/取消置顶 | 切换置顶状态，列表实时重排序 | `PUT /api/conversations/{id}` |
| 导出 | 获取完整消息，生成 Markdown 文件（含标题、导出时间、消息数），自动下载 | `GET /api/conversations/{id}` |
| 删除 | 弹出确认弹窗（"确定删除对话「标题」吗？此操作不可撤销"），确认后删除 | `DELETE /api/conversations/{id}` |

**删除的边界处理**：
- 删除当前正在查看的对话 → 清空消息区，回到欢迎页
- 删除非当前对话 → 仅从列表移除

**导出文件格式**：
```markdown
# 对话标题

> 导出时间: 2026-07-02 20:00:00
> 消息数: 5

---

### 用户

帮我搜索抖音上关于AI培训的视频

---

### 助手

好的，我来帮您搜索...
```

### 3.3 欢迎页（无对话空状态）

#### 3.3.1 功能概述

当没有对话消息时（`messages.length === 0`），对话区域展示欢迎页。这是一个极简居中布局，引导用户开始对话，同时展示动态精选案例降低冷启动焦虑。

#### 3.3.2 布局结构

从上到下，整体在可用空间内水平+垂直居中：

| 区块 | 内容 | 尺寸 |
|------|------|------|
| Logo + 品牌标识 | 104px 圆形 Logo + "超级员工" 标题 | Logo: 104×104px，标题: 40px 粗体 |
| 核心输入框 | 圆角矩形 textarea + 内嵌发送按钮 | 640px 宽，28px 圆角 |
| 精选案例 | 标题 + 三列卡片网格 | 640px 宽 |

**布局约束**：
- 不可上下滚动（`overflow: hidden`），所有内容一屏内完整展示
- 容器最大宽度 720px，各区块间距 40px
- `.messages-area.welcome-mode` 使用 `flex: 1 1 auto` 填满高度，使内容垂直居中生效

#### 3.3.3 核心输入框

**外观**：
- 大圆角矩形（`border-radius: 28px`），浅色边框 + 柔和阴影
- 内嵌发送按钮：40px 圆形，绝对定位在输入框右下角

**交互**：
- 占位文字：`输入 "/" 唤起工具和能力`
- Enter 键发送消息，Shift+Enter 换行
- 发送中状态：按钮显示 loading 旋转动画，输入框禁用
- 发送后清空输入框内容

#### 3.3.4 精选案例卡片

**功能**：从抖音动态搜索真实视频，展示为推荐案例卡片，点击即自动发送对话。

**加载流程**：
1. 页面加载时，收集最近 10 条对话标题
2. 调用 `POST /api/hermes/case-cards`，传入 `recent_titles` 和 `limit: 3`
3. 后端流程：
   - LLM 根据对话标题推断搜索关键词（超时 10s）
   - 无对话历史时使用默认关键词 `"AI营销自动化工具"`
   - 通过 headless Chromium 搜索抖音视频（超时 60s）
   - LLM 对搜索结果排序筛选，返回最优 3 条
   - 结果缓存 30 分钟
4. 前端渲染卡片

**卡片展示**：
- 三列等宽网格（768px 以下变单列）
- 每张卡片：视频封面图（130px 高，`object-fit: cover`）+ 视频标题
- 卡片圆角 12px，hover 时上浮 2px + 阴影加深

**卡片交互**：
- 点击卡片 → 将视频标题填入输入框 → 自动发送消息

**状态处理**：

| 状态 | 展示 |
|------|------|
| 加载中 | 卡片网格区域显示 loading 遮罩 |
| 加载成功 | 展示 3 张卡片 |
| 加载失败/无结果 | 显示"暂无推荐案例"（居中文字） |
| 抖音未登录 | 搜索返回空结果，同样显示"暂无推荐案例"（可接受） |

### 3.4 对话消息流

#### 3.4.1 功能概述

有对话消息时（`messages.length > 0`），对话区域展示消息流。支持文本、图片、视频、工具调用等多种消息类型，AI 回复通过 SSE 流式实时渲染。

#### 3.4.2 消息类型

| 类型 | 触发场景 | 渲染方式 |
|------|----------|----------|
| `text` | 用户输入 / AI 文本回复 | Markdown 渲染（GFM 语法 + 自动换行），经 DOMPurify 消毒防 XSS |
| `image` | AI 生成图片 | 图片卡片，点击打开全屏 Lightbox |
| `video` | AI 生成视频完成 | 内嵌视频播放器 + 操作栏 |
| `video_pending` | 视频生成中 | 进度卡片：旋转图标 + 提示词 + 状态文字 + 进度百分比 |
| `tool_result` | Agent 调用工具后 | 工具名称标签 + 状态色标（绿=success / 红=error）+ 结果摘要（截断 200 字符） |

#### 3.4.3 消息布局

每条消息为一行 flex 布局：**头像 + 消息内容**

| 角色 | 头像 | 消息样式 |
|------|------|----------|
| 用户 | 28px 圆形，显示用户名首字母大写 | 气泡包裹（`accent-soft` 背景，`border-radius: 12px 12px 12px 4px`，左下角小圆角指向头像） |
| Agent | 28px 圆形，显示系统 Logo 图片 | 无气泡，纯文本展示 |

**对齐规则**：
- 头像与消息内容顶部对齐（`align-items: flex-start`）
- 头像 `margin-top: 2px` 微调，使头像中心与第一行文字视觉居中
- 头像与内容间距 12px
- 消息间距 20px

#### 3.4.4 流式输出

**发起请求**：
- 用户发送消息后，通过 `POST /api/hermes/chat` 发起 SSE 流式请求
- 请求体：`{ model, messages, stream: true, agent_id }`
- `messages` 仅包含 `type === 'text'` 的用户和助手消息（过滤掉图片/视频/工具结果）

**SSE 事件处理**：

| 事件类型 | 前端处理 |
|----------|----------|
| `text` | 将 `content` 追加到流式文本缓冲区，实时 Markdown 渲染 |
| `tool_call` | 添加工具调用卡片到流式区域，状态为 `running`，显示工具名和参数摘要 |
| `tool_result` | 匹配对应工具卡片，更新状态为 `success` 或 `error`，显示结果摘要 |
| `image` | 添加图片到流式图片缓冲区 |
| `video_task` | 添加视频进度卡片，显示提示词和初始状态 |
| `video_status` | 更新对应视频卡片的进度百分比和状态 |
| `video` | 移除进度卡片，替换为视频播放器卡片 |
| `error` | 在流式文本末尾追加 `⚠️` + 错误内容 |
| `status` | 忽略（不渲染） |
| `done` | 忽略（流结束信号） |

**流式视觉**：
- 流式过程中，文本末尾显示闪烁光标 `▊`
- 工具调用卡片实时显示，用户可看到 Agent 正在执行什么操作
- 视频进度卡片实时更新百分比

**流结束后处理**：
1. 将完整流式文本作为一条 `assistant` 消息保存
2. 每个工具调用作为独立 `system` 消息保存（`type: tool_result`）
3. 每张图片作为独立 `assistant` 消息保存（`type: image`）
4. 视频进度卡片更新为视频卡片，或新增视频卡片
5. 清空所有流式缓冲区
6. 自动保存对话到后端
7. 刷新对话历史列表
8. 滚动到底部

**错误处理**：
- 请求失败（网络错误/非 200）：添加一条助手消息 `⚠️ 请求失败: {错误信息}`
- 401 未授权：自动重新登录后重试

#### 3.4.5 图片消息

- 图片以卡片形式内嵌在消息流中
- 点击图片 → 打开全屏 Lightbox 查看器（Element Plus `el-image-viewer`）
- Lightbox 支持缩放、旋转、拖动

#### 3.4.6 视频消息

视频消息包含内嵌播放器和底部操作栏：

| 操作 | 说明 |
|------|------|
| 放大 | 打开模态框播放视频（带 controls + autoplay） |
| 全屏 | 请求浏览器全屏播放 |
| 下载 | 触发文件下载 |

**视频模态框**：
- 居中覆盖层，包含视频播放器 + 操作按钮（全屏 / 关闭）
- 点击关闭按钮或模态框外部关闭

#### 3.4.7 视频生成进度卡片

当 AI 正在生成视频时，显示进度卡片：
- 旋转加载图标
- 提示词文本（用户描述的视频内容）
- 状态文字（如"生成中"）
- 进度百分比（0-100%）
- 生成完成后，卡片原地替换为视频播放器

### 3.5 底部输入区

#### 3.5.1 功能概述

对话模式下的消息输入区域，固定在对话区域底部。

#### 3.5.2 布局

- `textarea` 输入框（3 行高度）+ 发送按钮（水平排列）
- 占位文字：`输入指令，如：帮我搜索抖音上关于AI培训的视频，生成评论并发送`
- Enter 键发送消息
- 发送中状态：输入框禁用，发送按钮显示 loading 旋转动画

#### 3.5.3 发送逻辑

1. 获取输入文本，trim 后非空且非流式中才发送
2. 添加用户消息到消息列表
3. 清空输入框
4. 滚动到底部
5. 设置 `streaming = true`，发起 SSE 请求
6. 流结束后 `streaming = false`，保存对话，刷新列表

### 3.6 对话保存

#### 3.6.1 保存时机

每次 AI 回复流结束后自动保存。

#### 3.6.2 保存内容

| 字段 | 说明 |
|------|------|
| title | 第一条用户消息前 50 字符 |
| messages | 所有消息（角色、内容、类型、时间戳、图片URL、提示词、视频URL、任务ID、状态、进度） |
| agent_id | 当前 Agent ID |
| model | 使用的模型名 |

#### 3.6.3 保存逻辑

- 已有对话（`activeConvId` 存在）：`PUT /api/conversations/{id}`
- 新对话（`activeConvId` 为空）：`POST /api/conversations`，获取返回的 ID 存入 `activeConvId`
- 保存后刷新对话列表（`GET /api/conversations`）

### 3.7 快捷卡片

预置的快捷指令卡片，在欢迎页底部展示（与精选案例卡片不同，这些是静态预置的）：

| 卡片标题 | 指令内容 | 场景 |
|----------|----------|------|
| 搜索截流 | 搜索抖音 AI 培训视频并截流 | 获客场景 |
| 生成文案 | 生成 5 条护肤文案 | 内容创作 |
| 定时发布 | 今天 12 点发 3 个视频到抖音 | 自动化发布 |
| 数据查看 | 查看今日截流数据 | 数据分析 |
| 客户接待 | 给新客户发欢迎语 | 客户运营 |

点击快捷卡片 → 将指令内容填入输入框 → 自动发送消息。

## 4. AI 内容生成模块

### 4.1 功能概述

通过对话指令，AI 自主调用火山引擎方舟的豆包系列模型，生成图片、视频、语音、文案等内容。用户无需了解模型参数，用自然语言描述需求即可。

### 4.2 用户故事

- 作为运营人员，我希望说"帮我生成一张赛博朋克风格的城市夜景图"，AI 就能生成图片并显示在对话中
- 作为运营人员，我希望说"生成一段 5 秒的猫咪玩耍视频"，AI 就能创建视频任务并实时显示进度
- 作为运营人员，我希望说"用温柔的女声朗读这段文案"，AI 就能合成语音
- 作为运营人员，我希望说"帮我写 5 条护肤品的种草文案"，AI 就能生成多条文案供我选择

### 4.3 能力清单

#### 4.3.1 AI 图像生成

| 属性 | 说明 |
|------|------|
| 触发方式 | 对话指令，如"生成一张赛博朋克风格的城市图" |
| 支持模型 | 豆包文生图（doubao-image）/ SDXL / FLUX |
| 风格选项 | 写实(realistic) / 动漫(anime) / 赛博朋克(cyberpunk) / 油画(oil) / 水墨(ink) / 极简(minimal) / 3D / 像素(pixel) |
| 分辨率预设 | 1920×1920（默认）/ 2560×1440(16:9) / 1440×2560(9:16) / 2048×2048 / 2304×1728(4:3) / 3072×1296(21:9) |
| 自定义分辨率 | 支持，需 ≥ 368 万像素 |
| 结果展示 | 图片以卡片形式插入对话流，点击可全屏查看 |

**交互流程**：
1. 用户描述需求 → Agent 调用 `ai_image_generate` 工具
2. 工具返回图片 URL → SSE 推送 `image` 事件
3. 前端将图片作为独立消息插入对话流
4. 用户点击图片 → Lightbox 全屏查看

#### 4.3.2 AI 视频生成

| 属性 | 说明 |
|------|------|
| 触发方式 | 对话指令，如"生成一段 5 秒的海浪视频" |
| 支持模型 | 豆包视频生成（doubao-video）/ Seaweed |
| 生成模式 | 文生视频（纯文字描述）/ 图生视频（提供参考图片） |
| 视频时长 | 默认 5 秒，可指定 |
| 风格选项 | 写实(realistic) / 动漫(anime) / 电影感(cinematic) |
| 执行方式 | 异步任务，提交后返回 task_id |

**交互流程**：
1. 用户描述需求 → Agent 调用 `ai_video_create` 工具
2. 工具提交异步任务，返回 task_id → SSE 推送 `video_task` 事件
3. 前端显示视频进度卡片（旋转图标 + 提示词 + 状态 + 0%）
4. Agent 轮询 `ai_video_task_status` 查询进度 → SSE 推送 `video_status` 事件
5. 前端实时更新进度百分比
6. 视频生成完成 → SSE 推送 `video` 事件
7. 前端将进度卡片替换为视频播放器卡片
8. 用户可播放、放大、全屏、下载视频

**边界处理**：
- 生成失败：进度卡片状态变为 error，Agent 在对话中告知用户失败原因
- 生成超时：Agent 轮询超过合理时间后告知用户"视频生成超时，请稍后重试"

#### 4.3.3 AI 语音合成

| 属性 | 说明 |
|------|------|
| 触发方式 | 对话指令，如"用温柔的女声朗读这段文案" |
| 引擎 | 火山引擎豆包语音合成 |
| 声音选择 | 默认 `zh_female_xiaoyi`，可指定其他声音 ID |
| 情感选项 | 中性(neutral) / 开心(happy) / 悲伤(sad) / 兴奋(excited) / 平静(calm) / 愤怒(angry) |
| 语速调节 | 0.5x ~ 2.0x，默认 1.0x |
| 音调调节 | -100 ~ +100，默认 0 |
| 结果展示 | Agent 在对话中告知合成完成，提供音频文件路径 |

#### 4.3.4 声音克隆

| 属性 | 说明 |
|------|------|
| 触发方式 | 对话指令，如"用这个声音样本朗读这段文字" |
| 输入 | 声音样本文件（.wav/.mp3，10-30 秒）+ 要合成的文本 |
| 情感选项 | 中性 / 开心 / 悲伤 / 兴奋 |
| 结果展示 | Agent 在对话中告知克隆合成完成，提供音频文件路径 |

#### 4.3.5 AI 文案生成

| 属性 | 说明 |
|------|------|
| 触发方式 | 对话指令，如"帮我写 5 条护肤品的种草文案" |
| 执行方式 | Agent 直接通过 LLM 生成文本，无需调用额外工具 |
| 结果展示 | 文案以 Markdown 格式在对话流中展示，支持列表、加粗等格式 |

### 4.4 用户交互体验

**全程对话驱动**：
- 用户不需要填写表单、选择参数
- Agent 根据自然语言理解用户意图，自动选择合适的模型和参数
- 如果信息不足，Agent 主动追问（如"您想要什么风格？写实还是动漫？"）
- 所有生成结果直接出现在对话流中，用户可以继续对话调整

**结果可追溯**：
- 图片、视频、工具调用记录都保存在对话历史中
- 重新打开对话可以看到之前的生成结果
- 支持导出对话为 Markdown 文件

## 5. 视频剪辑模块

### 5.1 功能概述

通过对话指令，AI 调用视频剪辑工具对本地视频文件进行加工处理：裁剪、拼接、变速、叠加标题、音频处理、封面提取、模板渲染。

### 5.2 用户故事

- 作为运营人员，我希望说"把这段视频的前 10 秒裁剪出来"，AI 就能完成裁剪
- 作为运营人员，我希望说"把这三个视频拼接成一个"，AI 就能合并视频
- 作为运营人员，我希望说"给视频加上标题'新品上市'，字号 48"，AI 就能叠加文字
- 作为运营人员，我希望说"把视频原声音量降低到 30%，加上背景音乐"，AI 就能混音
- 作为运营人员，我希望说"从视频第 3 秒截取一帧作为封面"，AI 就能提取封面图

### 5.3 能力清单

#### 5.3.1 视频信息查询

| 属性 | 说明 |
|------|------|
| 触发方式 | 对话指令，如"查看这个视频的信息" |
| 输入 | 视频文件本地路径 |
| 输出 | 时长、分辨率、编码格式 |
| 用途 | Agent 在剪辑前先了解视频参数，做出合理的剪辑决策 |

#### 5.3.2 视频裁剪

| 属性 | 说明 |
|------|------|
| 触发方式 | 对话指令，如"裁剪视频第 5 秒到第 15 秒" |
| 输入 | 文件路径 + 开始时间（秒）+ 时长（秒） |
| 输出 | 裁剪后的视频文件 |
| Agent 行为 | 根据用户描述计算 start 和 duration 参数 |

#### 5.3.3 视频拼接

| 属性 | 说明 |
|------|------|
| 触发方式 | 对话指令，如"把这三个视频按顺序拼起来" |
| 输入 | 多个视频文件路径（逗号分隔） |
| 输出 | 拼接后的单一视频文件 |
| Agent 行为 | 收集用户提供的所有文件路径，组装为逗号分隔列表 |

#### 5.3.4 视频变速

| 属性 | 说明 |
|------|------|
| 触发方式 | 对话指令，如"把视频慢放一半"或"2 倍速快进" |
| 输入 | 文件路径 + 速度倍率（0.5 = 慢放一半，2.0 = 快进一倍） |
| 输出 | 变速后的视频文件 |

#### 5.3.5 叠加文字标题

| 属性 | 说明 |
|------|------|
| 触发方式 | 对话指令，如"在视频上加上标题'新品上市'" |
| 输入 | 文件路径 + 标题文字 + 字号（可选）+ 颜色（可选） |
| 输出 | 叠加文字后的视频文件 |
| 字体 | 可通过 `video_fonts` 工具查询可用字体列表 |

#### 5.3.6 音频处理

**替换音频**：

| 属性 | 说明 |
|------|------|
| 触发方式 | 对话指令，如"把视频的背景音换成这首歌" |
| 输入 | 视频路径 + 新音频文件路径 |
| 输出 | 替换音频后的视频文件 |

**混音（原声 + 背景音乐）**：

| 属性 | 说明 |
|------|------|
| 触发方式 | 对话指令，如"保留视频原声，音量降到 30%，加上背景音乐音量 70%" |
| 输入 | 视频路径 + BGM 文件路径 + 原声音量(0-1) + BGM 音量(0-1) |
| 输出 | 混音后的视频文件 |

#### 5.3.7 封面提取

| 属性 | 说明 |
|------|------|
| 触发方式 | 对话指令，如"从视频第 3 秒截取一帧作为封面" |
| 输入 | 文件路径 + 时间点（秒）+ 宽度（可选）+ 高度（可选） |
| 输出 | 封面图片文件 |
| 用途 | 用于发布视频时指定封面 |

#### 5.3.8 模板渲染

| 属性 | 说明 |
|------|------|
| 触发方式 | 对话指令，如"用模板给视频加上标题和字幕" |
| 前置步骤 | Agent 先调用 `video_templates` 列出可用模板，供用户选择 |
| 输入 | 模板 ID + 素材文件列表 + 标题 + 字幕（可选）+ 字体名（可选） |
| 输出 | 渲染后的视频文件（含标题 + 字幕） |

### 5.4 用户交互体验

**对话驱动的工作流**：
1. 用户提供视频文件路径（或从之前的生成结果获取）
2. Agent 先调用 `video_info` 了解视频参数
3. 用户描述剪辑需求
4. Agent 调用对应剪辑工具
5. 工具执行完成后，Agent 告知用户输出文件路径
6. 用户可以继续下达其他剪辑指令（链式操作）

**链式操作示例**：
```
用户: 帮我把这个视频裁剪前 10 秒
Agent: [调用 video_info] 这个视频总时长 30 秒，1920x1080...
       [调用 video_cut] 已裁剪前 10 秒，输出文件：output_cut.mp4
用户: 给裁剪后的视频加上标题"精彩片段"
Agent: [调用 video_add_title] 已添加标题，输出文件：output_title.mp4
用户: 再从第 3 秒截取一帧作为封面
Agent: [调用 video_extract_frame] 已提取封面，输出文件：cover.jpg
```

**模板使用流程**：
1. 用户说"用模板渲染视频"
2. Agent 调用 `video_templates` 获取模板列表
3. Agent 在对话中展示可用模板（名称 + 描述）
4. 用户选择模板
5. Agent 调用 `video_render`，传入模板 ID + 素材 + 标题

## 6. 多平台发布模块

### 6.1 功能概述

通过对话指令，AI 检查平台登录状态、管理登录/登出、将视频或图文内容发布到抖音、小红书、哔哩哔哩、快手、微信视频号等多个平台。支持即时发布和定时发布。

### 6.2 用户故事

- 作为运营人员，我希望说"检查一下抖音的登录状态"，AI 就能告诉我是否已登录
- 作为运营人员，我希望说"登录小红书"，AI 就能打开扫码登录页面
- 作为运营人员，我希望说"把这个视频发布到抖音，标题是'AI教程'"，AI 就能完成发布
- 作为运营人员，我希望说"今天下午 3 点把这条图文发到小红书和快手"，AI 就能定时发布
- 作为运营人员，我希望说"查看抖音上那条视频的播放量和点赞数"，AI 就能查询数据

### 6.3 支持平台

| 平台 | ID | 支持内容类型 |
|------|-----|-------------|
| 抖音 | douyin | 视频、图文 |
| 小红书 | xhs | 视频、图文笔记 |
| 哔哩哔哩 | bilibili | 视频 |
| 快手 | kuaishou | 视频、图文 |
| 微信视频号 | wechat_mp | 视频 |

### 6.4 能力清单

#### 6.4.1 平台登录管理

**查看所有平台状态**：

| 属性 | 说明 |
|------|------|
| 触发方式 | 对话指令，如"检查所有平台的登录状态" |
| 工具 | `platform_list` 或 `platform_health` |
| 输出 | 每个平台的状态：ready / error / uninitialized，是否已登录 |
| 特殊说明 | 微信(wechat_mp)需要桌面客户端运行，未运行时显示 error 是正常的 |

**查看单个平台详情**：

| 属性 | 说明 |
|------|------|
| 触发方式 | 对话指令，如"抖音的登录状态怎么样" |
| 工具 | `platform_status` |
| 输出 | 登录状态 + Cookie 有效性 |
| Agent 行为 | 发布前必须先调用此工具检查登录状态 |

**触发扫码登录**：

| 属性 | 说明 |
|------|------|
| 触发方式 | 对话指令，如"登录抖音" |
| 工具 | `platform_login` |
| 行为 | 在本地打开浏览器窗口，用户扫码完成登录后自动保存 Cookie |
| 耗时 | 约 10-60 秒（需用户手动操作） |
| Agent 提示 | 告知用户"正在打开登录页面，请扫码登录" |

**登出**：

| 属性 | 说明 |
|------|------|
| 触发方式 | 对话指令，如"退出抖音登录" |
| 工具 | `platform_logout` |
| 行为 | 清除平台登录态和 Cookie |

#### 6.4.2 视频发布

**直接发布**：

| 属性 | 说明 |
|------|------|
| 触发方式 | 对话指令，如"把这个视频发到抖音，标题'AI教程'，标签'AI,教程'" |
| 工具 | `platform_publish_direct` 或 `sau_upload_video` |
| 输入 | 平台ID + 视频文件路径 + 标题 + 描述（可选）+ 标签（可选）+ 封面图（可选） |
| 前置检查 | Agent 先调用 `platform_status` 检查登录状态 |

| 输出 | 发布成功返回 post_id |

**定时发布**：

| 属性 | 说明 |
|------|------|
| 触发方式 | 对话指令，如"今天下午 3 点把视频发到抖音" |

| 时间格式 | `YYYY-MM-DD HH:MM` |
| 行为 | 平台定时发布功能，到指定时间自动上传 |

**多平台发布**：

| 属性 | 说明 |
|------|------|
| 触发方式 | 对话指令，如"把视频同时发到抖音和小红书" |
| Agent 行为 | 依次调用发布工具，分别发布到每个平台 |

#### 6.4.3 图文发布

| 定时发布 | 支持，同视频定时发布 |

#### 6.4.4 发布数据查询

| 属性 | 说明 |
|------|------|
| 触发方式 | 对话指令，如"查看抖音上那条视频的数据" |
| 工具 | `platform_post_status` |
| 输入 | 平台ID + post_id（发布时返回） |
| 输出 | 播放量、点赞数、评论数、分享数 |

### 6.5 用户交互体验

**发布前检查流程**：
1. 用户说"把视频发到抖音"
2. Agent 调用 `platform_status` 检查抖音登录状态
3. 已登录 → 直接发布
4. 未登录 → Agent 说"抖音尚未登录，正在打开登录页面，请扫码" → 调用 `platform_login`
5. 用户扫码完成 → Agent 确认登录成功 → 继续发布

**发布结果反馈**：
- 成功：Agent 告知"已成功发布到抖音，视频ID: xxx"
- 失败：Agent 告知失败原因（如"标题过长"、"视频格式不支持"、"网络超时"等）

**多平台批量发布**：
- Agent 逐个平台执行发布
- 每个平台独立检查登录状态
- 汇总报告：哪些平台成功、哪些失败

**Headless 模式**：
- 发布操作默认使用 headless Chromium，不弹出浏览器窗口
- 仅扫码登录时需要有头浏览器（用户需要看到二维码）

## 7. 非功能需求

### 7.1 性能

- 流式输出首字延迟 ≤ 500ms
- 对话列表加载 ≤ 1s
- 精选案例搜索超时 60s，LLM 关键词推断超时 10s
- 精选案例缓存 30 分钟

### 7.2 兼容性

- 浏览器：Chrome 90+ / Edge 90+ / Firefox 88+
- 最佳分辨率：1920×1080
- 响应式断点：1279px / 1023px / 767px

### 7.3 安全

- 所有 `/api` 路由需要 JWT 认证
- Markdown 渲染经过 DOMPurify 消毒，防止 XSS
- 文件路径校验防止目录穿越

### 7.4 主题

- 亮色（Light）+ 暗色（Dark）
- 切换无刷新，CSS 变量平滑过渡
- 持久化存储，刷新自动恢复
